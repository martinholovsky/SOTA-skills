# /sota-audit report: Harbor `src/server` + `src/controller` + `src/go.mod`

**Posture: NOT READY for a multi-tenant deployment where project admins don't trust each other.** Authorization on several v2.0 API handlers is checked against the project named in the URL, but the object is then read or written by an ID from the path or body that is never tied to that project. Any authenticated user can create a project (the default `project_creation_restriction=everyone`), so in practice any user can cross the tenant boundary. Seven High findings. All but one of them (H-7) come from reading the code; none was exercised against a running instance.

- Tree: `VERSION` = `v2.5.1`. There is no git history (`.git` was removed), so `git rev-parse HEAD` fails with "not a git repository". Every finding is pinned to **v2.5.1 workspace w5, no commit**. Nothing was edited, so the tree is unchanged since the audit started.
- Audit date: 2026-10-07. Mode: `/sota-audit`, one context, light threat model.

## 5. Full evidence blocks

Every High below got **self-refutation only**: I re-read the code at the tree, not my notes. None got an independent refuter. See §8.

### H-1: Cross-project read/modify/delete of webhook policies (auth headers exposed)
- **Severity:** High. A cross-tenant read of credentials (`auth_header`) plus cross-tenant write and delete. Likelihood: any authenticated user, given default project creation.
- **Location:** `server/v2.0/handler/notification_policy.go:109-135` (Update), `:137-147` (Delete), `:149-161` (Get); `notification_job.go:34`.
- **Evidence:**
  - Update copies the body into the model (`lib.JSONCopy(policy, params.Policy)`, :116), sets `policy.ProjectID = projectID` (:129), then calls `webhookPolicyMgr.Update(ctx, policy)` (:130). `params.WebhookPolicyID` is never read.
  - The swagger `WebhookPolicy` has `id` (`api/v2.0/swagger.yaml:7909`), and the model maps `json:"id"` (`pkg/notification/policy/model/model.go:16`).
  - The DAO does `ormer.Update(policy)` by primary key (`pkg/notification/policy/dao/dao.go:89`).
  - Delete and Get use `params.WebhookPolicyID` directly (:143, :155).
  - The DAO Get/Delete use only `ID` (`dao.go:46-49`, `:131-133`).
  - The response maps `AuthHeader` (`handler/model/notification_policy.go:37`).
- **Mapping:** CWE-639; OWASP API1:2023 (BOLA); ASVS V4.2.1.
- **Impact:** An attacker who admins any project can:
  - read another project's webhook targets and `auth_header` (a credential for the victim's receiver);
  - delete the victim's webhook policies;
  - overwrite one by ID, which moves it into the attacker's project and replaces its targets, so the victim silently loses notifications.
- **Remediation:** In Get, Delete and Update, load by ID and compare: `p, _ := mgr.Get(ctx, params.WebhookPolicyID); if p.ProjectID != projectID { return NotFound }`. In Update, set `policy.ID = params.WebhookPolicyID`. Apply the same check in `ListWebhookJobs`.
- **Effort:** small.
- **Reproduction (static read path):**
  1. `PUT /api/v2.0/projects/{own}/webhook/policies/{any}` with body `{"id":<victim id>, ...}`
  2. → `notification_policy.go:111` authorizes `{own}`
  3. → `:116` copies the body id
  4. → `:130` → `pkg/notification/policy/manager.go:128-134` → `dao.go:89` updates row `id=<victim>`.

  For the read: `GET .../projects/{own}/webhook/policies/{victimID}` → `:151` authorizes `{own}` → `:155` `Get(victimID)` → `:160` returns targets including the auth header.

### H-2: Any project admin can read any background job's log and stop any execution (preheat API)
- **Severity:** High. The execution/task tables are shared across GC, replication, retention, scan, scan-all, webhook and preheat, so this is cross-tenant and system-level disclosure plus integrity.
- **Location:** `server/v2.0/handler/preheat.go:576-592` (GetExecution), `:644-659` (StopExecution), `:682-717` (ListTasks), `:720-731` (GetPreheatLog).
- **Evidence:**
  - `api.taskCtl.GetLog(ctx, params.TaskID)` (:725) and `api.executionCtl.Stop(ctx, params.ExecutionID)` (:650) are called after only `RequireProjectAccess(params.ProjectName, ...)`.
  - `controller/task/controller.go:76-78` and `execution_controller.go:56-58` pass straight through.
  - `pkg/task/task.go:233-238` fetches the task by ID and returns the jobservice log, with no vendor or project filter.
- **Mapping:** CWE-639, CWE-284; API1:2023, API5:2023.
- **Impact:** Read job logs of any task: replication (registry endpoints, repository names), other tenants' scans, GC. Stop any running GC, replication, retention or scan execution, which is a cross-tenant DoS of maintenance and security scanning. Who can do this: preheat permissions belong to `projectAdmin` (`common/rbac/project/rbac_role.go:121-125`), and project creation is open to everyone by default.
- **Remediation:** Resolve the policy from `(project, PreheatPolicyName)`, then require `exec.VendorType == job.P2PPreheat && exec.VendorID == policy.ID` before Get/Stop/List. For tasks and logs, also require `task.ExecutionID == params.ExecutionID`.
- **Effort:** small.
- **Reproduction:**
  1. `GET /api/v2.0/projects/{own}/preheat/policies/x/executions/1/tasks/{N}/logs`
  2. → `preheat.go:721` authorizes `{own}`
  3. → `:725` → `controller/task/controller.go:77` → `pkg/task/task.go:234-238`. Path policy `x` and execution `1` are never read.

### H-3: Retention endpoints expose any task's log and stop any execution
- **Severity:** High. It is the same primitive as H-2, reached through a second API. Maintainers hold `TagRetention` permissions (`rbac_role.go:157-162`).
- **Location:** `server/v2.0/handler/retention.go:265-281` (stop), `:313-341` (tasks), `:343-358` (log).
- **Evidence:** Authorization is performed on policy `params.ID`, then the handler acts on `params.Eid` / `params.Tid`. `controller/retention/controller.go:257-270` stops the execution regardless of its vendor. `:363-365` returns `taskMgr.GetLog(taskID)` for any task. `:322-335` filters by `VendorType=Retention` but not by policy, so another project's retention tasks (including repository names, `:341`) are listed.
- **Mapping:** CWE-639; API1:2023.
- **Impact:** Same as H-2, available to maintainers. It also discloses private repository names of other projects.
- **Remediation:** `e := execMgr.Get(eid); if e.VendorType != job.Retention || e.VendorID != params.ID { NotFound }`. For logs, load the task and check its execution in the same way.
- **Effort:** small.
- **Reproduction:**
  1. Create a retention policy on your own project (`POST /retentions`, scope = own project).
  2. `GET /api/v2.0/retentions/{ownID}/executions/1/tasks/{N}/logs`
  3. → `retention.go:344-348` authorizes `ownID` → `:353` → `controller.go:364`.

### H-4: Preheat UpdatePolicy overwrites any project's policy
- **Severity:** High. Cross-tenant write.
- **Location:** `server/v2.0/handler/preheat.go:257-272`; conversion `:468-479`; `controller/p2p/preheat/controller.go:328-337`.
- **Evidence:** `convertParamPolicyToModelPolicy` copies `ID: model.ID` and `ProjectID: model.ProjectID` from the body. UpdatePolicy neither resolves the path project nor overrides those fields (compare CreatePolicy, `:244-245`, which does override). The controller looks the policy up by `schema.ID` (:334).
- **Mapping:** CWE-639, CWE-915; API1/API3:2023.
- **Impact:** Rewrite another tenant's preheat policy: filters, trigger, provider, enabled, even its `project_id`. That alters what is pushed to P2P providers and when.
- **Remediation:** `project := GetByName(params.ProjectName); old := GetPolicyByName(project.ProjectID, params.PreheatPolicyName); policy.ID = old.ID; policy.ProjectID = project.ProjectID`.
- **Effort:** trivial.
- **Reproduction:** `PUT /projects/{own}/preheat/policies/any` with body `{"id":<victim>, "project_id":<victim project>, ...}` → `:258` authorizes `{own}` → `:262` → `:267` → `controller.go:334`.

### H-5: Immutable-tag rules of any project can be deleted, disabled or rewritten
- **Severity:** High. It removes another tenant's integrity control (tag immutability).
- **Location:** `server/v2.0/handler/immutable.go:56-67` (delete uses `params.ImmutableRuleID`), `:69-89` (update uses body `ID`); `controller/immutable/controller.go:59-70`; `pkg/immutable/dao/dao.go:47-60` (`ormer.Update(ir, "TagFilter")` by primary key; `ProjectID` is assigned but is not a predicate). `EnableImmutableRule(ctx, m.ID, ...)` toggles by ID alone.
- **Mapping:** CWE-639; API1:2023.
- **Impact:** A maintainer of any project can delete or disable a victim project's immutable-tag rules, so the victim's tags become overwritable. The victim's audit trail never records it (M-6).
- **Remediation:** Get the rule and require `rule.ProjectID == projectID`. Use the path ID.
- **Effort:** small.
- **Reproduction:** `DELETE /projects/{own}/immutabletagrules/{victimRuleID}` → `:58` authorizes `{own}` → `:62` → `DeleteImmutableRule(id)`.

### H-6: UpdateRobot lets a project admin disable, re-scope or extend any other project's robot
- **Severity:** High. Cross-tenant write to a credential object; it breaks other tenants' CI pulls and pushes.
- **Location:** `server/v2.0/handler/robot.go:186-208`, `:282-319`; `controller/robot/controller.go:142-158`.
- **Evidence:** The robot `r` is loaded by path `RobotID` (:191). Authorization is `requireAccess(ctx, params.Robot.Level, params.Robot.Permissions[0].Namespace, update)` (:287), which is body-controlled. Only level and name must match (:291). Then `r.Disabled`, `Duration`/`ExpiresAt` and `Permissions` are taken from the body (:295-311), and the controller deletes and recreates the RBAC permissions (:151-155).
  - The v1 API does this correctly with `q.KeyWords{"ProjectID": pro.ProjectID, "ID": params.RobotID}` (`robotV1.go:215`).
  - Delete, Get and RefreshSec in v2 also check `r.ProjectID` (:90, :179, :220). This is a deviation from the codebase's own pattern.
- **Mapping:** CWE-639, CWE-285; API1:2023.
- **Impact:** Disable or strip another project's robot accounts, or set them to never expire. The secret is not disclosed and access is not gained, since permissions can only point at a namespace the attacker controls.
- **Remediation:** Add `requireAccess(ctx, r.Level, r.ProjectID, rbac.ActionUpdate)` before :287, and reject a body namespace that differs from the robot's project.
- **Effort:** trivial.
- **Reproduction:** `PUT /api/v2.0/robots/{victimRobotID}` with body `{level:"project", name:<victim name>, disable:true, permissions:[{kind:"project", namespace:"<own>", access:[...]}]}` → `:191` → `:287` authorizes `<own>` → `:313` updates.

### H-7: Unauthenticated icon endpoint decodes user-supplied images with no dimension bound (needs verification)
- **Severity:** High *if* the decoder behaves as read. Availability of the whole multi-tenant core. Marked **needs verification**: not executed (see §9).
- **Location:** `server/v2.0/handler/icon.go:37-46` (no `Require*` call); `controller/icon/controller.go:117-136` (pulls any artifact's icon blob by digest, then `image.Decode`); `:161` (unbounded `sync.Map` cache); `controller/artifact/annotation/v1alpha1.go:64-98` (any pushed OCI manifest whose layer carries the `io.goharbor.artifact.v1alpha1.icon` annotation becomes an icon).
- **Chain legs:**
  - *reaches*: any project developer can push such a layer.
  - *acts*: an anonymous `GET /api/v2.0/icons/{digest}` runs `image.Decode` (gif/jpeg/png registered, :20-25) on the full blob, with no `DecodeConfig` bound.
  - *crosses*: the core process is shared by all tenants.
  - *channel*: not applicable (availability).
- **Secondary:** the icon of an artifact in a private project is served to anyone who knows the digest. That is a minor confidentiality leak.
- **Mapping:** CWE-400, CWE-409; API4:2023; code-security 09.
- **Remediation:** `cfg, _, err := image.DecodeConfig(r)` and reject when `cfg.Width*cfg.Height` exceeds a small cap (for example 4096×4096). Wrap the reader in `io.LimitReader`. Require project read access on the owning artifact. Replace `sync.Map` with a size-bounded LRU.
- **Effort:** small.
- **Reproduction:** static read path only, as above. Verification needs a disposable instance running the shipped toolchain (Go 1.17.7).

### Medium (abridged evidence)
- **M-1 (inert control).** `v1alpha1.go:83` reads `ioutil.ReadAll(io.LimitReader(icon, 1<<20))` and then tests `err == io.EOF` (:85). `ReadAll` never returns `io.EOF`, and `LimitReader` truncates silently, so blobs over 1 MB pass. Falsification question: if this check were deleted, nothing observable would differ. No test exercises it with a file over 1 MB.
- **M-2.** `retention.go:197-210` sets `p.ID = params.ID`, but `requireAccess` uses the body `p.Scope.Reference`. `controller/retention/controller.go:162` writes the attacker's scope and rules into the victim's policy. Rated below High because the victim project's artifacts are not acted on: the policy now scopes to the attacker's project. The victim silently loses retention.
- **M-3.** Hook routes (`server/route.go:53-59`) reach `jobStatusHandler.ServeHTTP` with no check. `pkg/task/hook.go:47-108` updates status and runs check-in processors (scan report ingestion) for whatever `job_id` is posted. Mitigations: job IDs are opaque, and nginx blocks the path in compose (`nginx.https.conf.jinja:227`). Deciding assumption: Medium behind that nginx; High wherever core is directly reachable (other ingress, pod network without NetworkPolicy). **Needs verification** per deployment.
- **M-4.** `validateTargets` only reconstructs `scheme://host/path` (:228-233). It does not deny `127.0.0.0/8`, RFC1918, `169.254.169.254` or the core/jobservice service names. A project admin can make jobservice POST event JSON with a chosen `auth_header` to internal services (blind SSRF). `skip_cert_verify` is user-settable.
- **M-5.** The global chain (`core/middlewares/middlewares.go`, read for context) has no limiter. A sweep for `rate.?limit|ratelimit|limiter|x/time/rate` with `/usr/bin/grep` over server+controller found only `controller/replication/transfer/iothrottler.go` (bandwidth); that hit is the instrument's positive control. Basic auth runs `auth.Login` on every request (`basic_auth.go:66`). The core lock (`core/auth/authenticator.go:33-35`) is a 1.5 s per-username freeze, not a per-IP limit. Self-registration (`user.go:357-379`) has no CAPTCHA or throttle.
- **M-6.** The audit-log handler subscribes to 8 topics only (`init.go:51-58`: push/pull/delete artifact, create/delete project, delete repo, create/delete tag). No event exists for configuration, sysadmin grant (`user.go:327`), robot, member, webhook, retention or immutable changes, so H-1..H-6 abuse leaves no audit record. Subscription errors are discarded (gosec G104 ×29 in that file), so a failed registration is silent.
- **M-7.** Every proxied HEAD spawns a goroutine that polls `EnsureTag` up to 60×10 s (`proxy.go:244-258`), with no dedupe and no shutdown. `ProxyBlob` spawns a second full upstream download per request (`controller/proxy/controller.go:269-274`). `ProxyManifest`'s goroutine uses the **request** `ctx` after the response returns (:231, :236), which is cancelled. Reachable by anonymous pulls on a public proxy-cache project.
- **M-8.** `ToUserResp` includes `OIDCUserMeta.PlainSecret`. `getUserByID` sets `WithOIDCInfo` for any id>1 under OIDC, and `requireReadable` admits any holder of system `user:read`.
- **M-9.** Per-module rows in Appendix B.

## 8. Refutation: the weaker form

Every Critical/High got a **self-refutation only**: one context re-reading the code at the tree, defaulting to REFUTED where ambiguous. None got the independent refuter the standard requires (`sota` rules/03 §4a). Escalate to `/sota-deep-audit` before anyone relies on H-1..H-7.

What the self-refutation checked:
- **H-1:** Could `id` be read-only in the swagger and so not bound? No. It is a plain property (swagger.yaml:7909), and the Go model tag is `json:"id"`. The Update path never reads `params.WebhookPolicyID`. **Survives.**
- **H-2/H-3:** Is there a vendor filter deeper down? `pkg/task/task.go:233-238` and `execution.go:249+` have none. **Survives.**
- **H-4:** Compared against CreatePolicy, which does override `ProjectID`; UpdatePolicy does not. **Survives.**
- **H-5:** Does beego `Update(ir, "TagFilter")` add `project_id` to the WHERE clause? No; it updates by primary key. The toggle path is ID-only. **Survives.**
- **H-6:** Is `requireAccess` called against `r.ProjectID` anywhere before line 287? No. **Survives.** Downgraded from "escalation" to "tamper": the namespace must be the attacker's own.
- **H-7:** Not refutable statically in either direction. Kept at High, labelled **needs verification**.
- **Pattern sweep:** after the refutations, I swept every handler that takes an object ID (census, Appendix A). Correct implementations exist in label, member (DAO `where project_id = ? and id = ?`, `pkg/member/dao/dao.go:171,181`), robot v1, robot v2 delete/get/refresh, and repository. The sweep is what produced H-2/H-3 (shared task IDs) and L-1/L-2.

Advisory/CVE identifiers for H-1..H-6 were **not looked up** (no network). Some may match published Harbor 2.5.x advisories. Do not treat them as novel without checking.
