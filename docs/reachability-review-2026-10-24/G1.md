### F1 — Ray / notebook / pipeline-UI control planes: HIGH rule, no probe

- **class:** S1
- **severity:** High
- **file:line:** `skills/sota-ml-engineering/rules/01-ml-systems-architecture.md:79-85`
- **quote:** "Compute control planes are remote code execution by design: a Ray dashboard / job-submission API, a notebook server or a pipeline UI (e.g. Kubeflow) that accepts a job runs it. None is ever reachable unauthenticated or from outside its trust domain. … set `RAY_AUTH_MODE=token` *and* keep network isolation. HIGH on sight when exposed."
- **checklist checked:** `01:113-135` (all seven items). The only trust-domain probe, `01:129-132`, greps `mlflow (server|ui)` without `app-name`, plus a manual question about training-job credentials. Nothing looks for Ray, a Jupyter server, Kubeflow, `RAY_AUTH_MODE` or an exposed dashboard port.
- **counterpart search:** `git grep -n -iE 'RAY_AUTH_MODE|ray dashboard|CVE-2023-48022' -- skills/` finds only `01:79-85`. Nothing elsewhere covers it, and nothing points to a file that does.
- **why:** this is the RCE-by-design surface the section itself rates HIGH on sight. An auditor running the checklist checks MLflow and stops, so an exposed Ray jobs API (CVE-2023-48022) passes the audit.
- **proposed fix:** add a §6 checklist item to `sota-ml-engineering/rules/01`. It should grep for `ray start|ray.init|RayCluster|dashboard-host|jupyter (lab|notebook|server)|kubeflow` and for an absent or `!= token` `RAY_AUTH_MODE`, plus a manual check that no control plane is reachable from outside its trust domain.
- **confidence:** high
