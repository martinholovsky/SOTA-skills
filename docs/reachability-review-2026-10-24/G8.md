### F1 — MessagePack (and DB-TLS) insecure defaults live only in the build file; the deserialization section never names them

- **class:** R3 (with an R2 component)
- **severity:** High
- **file:line:** `skills/sota-dotnet/rules/06-build-tooling-ci.md:86-88`, `:275-276`; `skills/sota-dotnet/rules/04-security.md:19-97` (§2), `:381-382`
- **quote:** 06:86-88 "**MessagePack-CSharp** `MessagePackSerializerOptions.Security` defaults to `MessagePackSecurity.TrustedData`; set `.WithSecurity(MessagePackSecurity.UntrustedData)` for anything from outside." The probe is 06:275-276 ("MessagePack deserialization in a file that never opts into `UntrustedData`"), and it sits inside the checklist item titled "**New dependency adopted unvetted, or a library's insecure default left on**" (06:263).
- **trigger quote:** SKILL.md:96, row for 04: "Any input crossing a trust boundary: SQL …, legacy serializers (`BinaryFormatter` removed .NET 9 …) + JSON `TypeNameHandling` + `DataSet.ReadXml` …". BUILD step 1 (SKILL.md:42-43): "A web API touching untrusted input + a DB + async needs `02`, `03`, `04`." Neither the row nor the BUILD step sends a deserialization task to 06. The 04 deserialization probe (04:381-382) greps `BinaryFormatter|NetDataContractSerializer|…|TypeNameHandling` and nothing else.
- **why:** Take a task like "accept MessagePack payloads from devices" or "switch our SignalR hub to the MessagePack protocol". That task loads 04 §2, the deserialization home, and `git grep -i messagepack skills/sota-dotnet/` finds no hit in 04 (MessagePack appears only at 06:86-87, 124 and 275-276). So the builder never learns that the library defaults to `TrustedData`. An auditor who runs 04's "Deserialization — CRITICAL" probe gets a clean result on exactly that code. The only probe is buried in an item about new dependencies. 06 has a second case of the same shape: Npgsql `SslMode=Prefer` and `TrustServerCertificate=True` (06:88-96, probe 06:269-271). 04 §5 "TLS" (04:263-271) is where a reader looks for those, and it never mentions database-connection TLS (`git grep -iE 'npgsql|TrustServerCertificate|SslMode' 04-security.md` returns nothing).
- **proposed fix:** Add a MessagePack bullet to 04 §2 (`TrustedData` default, use `UntrustedData`, plus the typeless-resolver warning), and move the 06:275-276 probe into 04's "Deserialization — CRITICAL" item. Also add a one-line pointer from 04 §5 TLS to 06 §3 for DB-client TLS defaults.
- **confidence:** high
