### F1 — Secrets AUDIT procedure never selects four of its five rules files

- **class:** R2
- **severity:** High
- **file:line:** `skills/sota-secrets-management/SKILL.md:65-95`, `:121-124`
- **quote:** AUDIT mode is a self-contained "Sweep procedure": "1. **Tooling pass** … 2. **Manual grep pass** … 3. **History pass** … 4. **Handling pass (misuse, not just leaks)** … 5. **Verify and triage**" (`:71-95`), ending "whether git history is affected (if so, remediation must include rotation + history purge per [`rules/04-detection-and-remediation.md`]…)" (`:121-123`).
- **trigger quote:** The only "walk the checklists" instruction is in BUILD: "7. **Self-review against the Audit checklist** at the end of every rules file you used." (`:63`). The only index row that names auditing is rules/04: "running an AUDIT sweep" (`:133`). The other rows read as BUILD triggers: rules/01 "Generating secrets … setting rotation/expiry/revocation policy" (`:130`), rules/02 "Choosing where a secret lives" (`:131`), rules/05 "Handling a specific credential class" (`:134`).
- **why:** An auditor following AUDIT mode runs the leak sweep and the handling pass, and reaches rules/04 at most. These High probes then never run:
  - `rules/01:331-334`: "Rotation tests the pending credential before promoting it … High"
  - `rules/02:312-314`: "No secret on a volume shared across deployments … High"
  - `rules/05:299-301`: "Wrapped/stored keys are integrity-protected … High"
  - `rules/05:302-304`: "Keys whose loss is data loss are backed up … High"
  - `rules/01:350-351`: OIDC `sub` pinning
  - `rules/02:297-298`: Vault policies
  - `rules/05:294-296`: JWT alg pinning

  The handling pass (step 4) names a few of these topics in prose ("missing rotation/expiry", "overly broad token scopes"). It never loads the files that hold the probes. Every other skill in this group tells AUDIT to walk every relevant file's checklist; for example, devsecops `SKILL.md:42-43` says "for each, walk the relevant Audit checklist at the end of every rules file".
- **proposed fix:** Add a step to `sota-secrets-management/SKILL.md` AUDIT mode: "6. Walk the Audit checklist at the end of every rules file (01–05) against what the sweep found; rules/04 alone covers leaks, not lifecycle, storage or credential-type handling."
- **confidence:** high
