# The invariants — what fails the build, and the incident behind each one

`scripts/check-invariants.sh` runs the checks below and fails the build on any of them, in
pre-commit and in CI. This table was **offloaded out of [AGENTS.md](../AGENTS.md) on
2026-09-13**, because AGENTS.md loads into *every* session under a 200-line cap and each new
invariant cost it a row — and every breach of it was exactly that. The
cap now constrains the always-loaded file, and this reference grows freely.

One line each. The full *rationale* lives at the point of use in the script's own header;
the practical "what this means for your PR" version is in
[CONTRIBUTING.md](../CONTRIBUTING.md#the-invariants-enforced).

| # | The build fails when… |
|---|---|
| 1 | a **skill** file (`skills/*/SKILL.md`, `skills/*/rules/*.md`) exceeds **500 lines** |
| 2 | a `skills/*/rules/*.md` doesn't end with `## Audit checklist`, **or carries more than one** — the last-heading test passes on a duplicate, and five files shipped that way with six stranded bullets in the block a reader has already scrolled past |
| 3 | an internal-name denylist hits (the library must stay generic) |
| 4 | a `SKILL.md` `description` exceeds **1024 chars** (spec cap — loaders silently skip it), is unquoted YAML containing `: `, or either `name`/`description` contains an **XML tag**; also a reserved word (`anthropic`, `claude`) in `name` |
| 5 | `VERSION`, `plugin.json` and the CHANGELOG top entry disagree, or a tag is ahead of `VERSION` |
| 6 | a count-bearing surface drifts from a recount of `skills/` (the social-preview pill and README alt are **"N+" floors**) |
| 7 | a skill is missing from the router's routing table (`skills/sota/SKILL.md`) **or** the library map (`skills/sota/rules/04`) — two files since the map was offloaded |
| 8 | a relative Markdown link to a `*.md` target doesn't resolve |
| 9 | `CHANGELOG.md` carries more than one `## [Unreleased]`, or it isn't the top entry |
| 10 | a `rules/*.md` isn't referenced by its own `SKILL.md` — written, capped, checklist-ed, and never loaded |
| 11 | `LAST-VERIFIED` moves without a sweep. Escapes: a sweep-shaped diff (≥ 20 skill files), or a CHANGELOG line naming **both** the token and the stamp's new date — a bare mention is not a declaration (tightened 2026-09-14, after a mention twice disarmed probe 11). The only **diff-based** check; skips with a note when there's no merge base |
| 12 | an `assets/*.png` is older than the `*.html` it renders — the README embeds the *image*, never the source, so an un-rendered fix reaches nobody. Escape: `[no-render]` in the commit subject |
| 13 | a scoreboard row in `evals/results/RESULTS.md` leaves its `Samples` cell empty |
| 14 | a **release** (VERSION changed) carries no `**Front door checked:**` line in its CHANGELOG section, or a declared term is missing from `README.md`/`docs/INDEX.md` **or** from the release's own entry |
| 15 | the **library map** (`skills/sota/rules/04`, offloaded out of the router) omits a `rules/NN` file that exists, or names one that doesn't — checks 7 and 10 both miss this, and `rules/11` went unlisted for two releases |
| 16 | the hook `README.md` **documents** differs from the one `install.sh` **writes** (`HOOK_CMD`) — the README's is what a reader copies by hand, so a stale block is the version that spreads |
| 17 | a document that **describes** the checks disagrees with them — a stated count that isn't the script's, or a restated negative-control coverage list that isn't the harness's. Counts inside `"quotes"` are read as history, not claims. **`README.md` joined the checked set 2026-09-10**, and counts spelled out in *words* are read too: it said "Twenty-five invariants" against a script with 29 for four releases, and neither the file nor the form was in scope |
| 18 | a **`§` section reference** resolves nowhere — invariant 8 reads only `[text](file.md)` links, so ~1,300 prose references went unchecked and broke silently on any renumber or split. An RFC's section (`RFC 9110 §15.6.4`) is external, not a local reference — only when the RFC number sits right before the `§` (2026-10-26, probe 18c) |
| 19 | a **check has no known-bad** and no pinned reason it cannot — and the exempt set may not *grow*, since silencing the coverage check by exempting your new check is a one-line move. Runs on every invocation (~50 ms), not behind a flag |
| 20 | the router's **§AUDIT** section changes without its pin being re-read — §BUILD has been pinned since v1.15.0 and caught drift twice; §AUDIT had nothing, and `run-repo-audit.py` pastes the whole router. Bumping the pin is the forcing function to re-read `sota/rules/01` §5 |
| 21 | a **CHANGELOG version below the top entry has no git tag** — invariant 5 checks a tag is never *ahead* of VERSION; nothing checked the other way, and v1.30.0 and v1.31.2 both shipped untagged and unreachable. The top entry is exempt: it is tagged after the merge |
| 22 | a **`- [ ]` checklist bullet is stranded inside a code fence** in a skill file — it renders as sample output, so no auditor reads it. Two landed in `sota-code-security` rules/11 §2.2 in PR #226 and sat there three weeks; invariant 2 tracks fence state but only for the *heading*, and the line count never changed |
| 23 | a **CHANGELOG version heading has no `[X.Y.Z]:` link reference**, an **orphan ref** whose heading lives in another file, or a ref pointing at the wrong tag — sibling of 21, failing independently of it. A heading with no ref is not a broken link: Markdown renders it as literal text, so invariant 8 never sees it. Four consecutive releases shipped that way. Compares **sets per file**, never counts |
| 24 | **this file** reaches 200 lines, or `CLAUDE.md`/`GEMINI.md` stop being symlinks to it — it loads into *every* session, which is the whole reason for the cap, and that reason depends on the symlinks. A **cap, not a target** (settled 2026-09-06); it had already been breached twice, at 201 and 202, each time by adding an invariant's own table row |
| 25 | the number of **eval CLI flags undocumented in `evals/README.md`** rises above the pin. A ratchet, not a rule: `--no-gate-arm` shipped documented in the README index and in `--help` but not in the harness's own front door, while 27 pre-existing generic flags (`--json`, `--build-model`) would make a strict rule open red and get it disabled. Fails closed if the scan finds **no** flags |
| 26 | the roadmap's **open set or totals disagree with the ledger** — the stated open count, the header's open list, the ledger rows marked `**OPEN`, an item cited in the priorities table that is not open, or a `Of N items, M are closed` / `All N items` total that does not match the ledger rows. Status lives in **one** place (the row marker); the rest is derived. Three drifts in one session, plus a fourth live when the check was written (header said 8, rows said 5). **The totals half was added 2026-09-21 after a third instance**: `Of 58 items, 55 are closed` against a 59-row ledger, in a different section from the gated header line, so it drifted alone — invariant 30 cannot reach it because its scope stops at the next heading |
| 27 | an **ADOPTION-LOG deferral names no revisit trigger** — its own rule said every deferral carries a revisit condition, in prose, and prose drifted: the roadmap said *"the deferred row"*, singular, while three existed and one had resolved the day before elsewhere. The marker's **own cell** is checked, not the row: a first draft passed a row because "revisit" sat in a different cell. **And the converse** (2026-10-23): a row naming a revisit trigger without the marker, and without saying it was resolved, fails. Five live deferrals had been written as `**deferred**` and similar shapes, invisible to this check and to `/sota-resume` |
| 28 | an **`evals/cases/*.jsonl` declares no `SELECTION RULE`** — building a set from the cases a model got wrong measures the selection, not the system. Held at 20 sets, then two were added and one skipped it: `prompt-independence.jsonl`, whose rule lived in the results doc and not in the case file, in the set backing the **+0.509** headline |
| 29 | a **release changes a skill `description` and declares no routing check** — a description is the entire auto-load classifier, so adding one competes for every neighbour's traffic: `sota-skill-security` (v1.35.0) took `r1_token_count` from `sota-llm-engineering` 3/3 to 0/3 and was live for a day with invariants 4, 7 and 15 all green. Fires only on a release whose extracted description **map** differs from the merge base's; the escape is a `**Routing checked:**` line naming an artifact that must exist, mention the regression set, **and be dated on or after the day the descriptions last changed** (the date comes from its `evals/results/<date>/` path). The currency half was added 2026-09-20: existence-only meant a release could satisfy the gate by pointing at a months-old run, so the declaration resolved, the gate went green, and the classifier was never re-measured — a control checked for existence rather than currency. Day granularity, and a run plus a later same-day description edit both pass |
| 30 | a **count stated in prose disagrees with the list it counts** — declared with a `<!-- count-check: PATTERN -->` marker above the claim, which counts matches from the marker to the next heading. `README.md` said *"Eleven classes of defect"* over a list of **26**: correct when written 2026-08-27, fifteen behind seventeen days later, and unreachable by every neighbouring gate (6 counts the `skills/` tree, 17 counts claims about the *scripts*, 26 counts the roadmap's open set). Opt-in by measurement, not by taste — a sweep for `<number-word> <plural-noun>` returns ~200 hits across `docs/`, nearly all historical prose, and a gate that opens red gets disabled |
| 31 | a **new rule section ships with no line in `docs/ADOPTION-LOG.md`** — diff-based. All thirty other checks assert structure, consistency or a declaration, and **none looks at whether a rule is true**; that is semantic and a fuzzy gate gets disabled. So this gates the thing that is mechanical — whether the rule went through review at all. An *external* proposal always reaches the ledger; a rule its author both **found and adopted** never does, and that is the path that skips scrutiny: `rules/12` §1d shipped on 30 green checks and an adversarial read returned **eleven** defects. A heading that existed in any rules file at the merge base is **exempt**, so a split stays free — without that, the check would fire on every split and be disabled |
| 32 | an **absence reported through `cmd 2>/dev/null \|\| echo "missing X"`** inside a prescriptive ```sh/```bash block in `skills/**` or `commands/**`. The `\|\|` arm means *"the pattern was absent"*; it fires on **every** non-zero exit and the `2>/dev/null` has already destroyed the reason — `grep` exits `1` for no-match and `2` for an unreadable path. With one missing path in the list the line printed the match it had just found **and** the verdict contradicting it. **Directional: it manufactures findings about other people's code**, so the output looks like a real defect and gets filed. Shipped in the audit checklists of **nine skills** (13 sites) until v1.42.2, field-reported, and invisible to every other gate. Not shellcheck's job — measured, `shellcheck -S style` exits **0** on the exact line, and linting all 161 fenced blocks yields 19 errors that are almost all fragment artifacts, which is a gate that opens red and gets disabled. ```console is exempt: a transcript is documentation (`rules/06` §2d demonstrates the broken form), and `\|\| true` is the documented best-effort write |
| 33 | a **top-level area is tracked but absent from the coverage table** in `docs/CONVENTIONS-LEDGER.md`, or the table declares an area that no longer exists. Enforcement density is uneven and unevenness is **invisible** — an ungated area looks exactly like a covered one. Measured 2026-09-16: `skills/**` (70,200 lines) carries ~20 of the checks; `commands/**` — 494 lines of instructions an agent executes on invocation, in any project — carried **two**, and nobody had decided that. Deliberately a **declaration, not a ratio**: an invariants-per-KLOC floor is arbitrary and gets tuned until it passes, so this forces the decision instead, exactly as 19, 27 and 28 do. Worth gating because **ten areas appeared in three months** and the newest arrived under-covered |
| 34 | a **version this repo claims for itself does not exist** — a rules-file header saying which release a section moved in is written *before the cut decides minor vs patch*, so guessing minor and shipping patch points the reader at a release that never existed. **Four times, twice in one session**: `v1.43.0` (really v1.42.2, 5 sites), `v1.36.4` (v1.37.0), `v1.41.3` (v1.42.0), `v1.42.3` (unreleased) — the fourth written **three hours after the third was fixed**, by the same author, in a commit whose message named the mechanism. Scope is the design work and was measured first: *every* `vX.Y.Z` is unshippable (35 unresolved, nearly all third-party), and our own `v1.*` namespace still catches placeholder image tags. What separates them is **grammar** — our claims read *at*/*in*/*since*/*·* `v1.42.2`; a placeholder never does. 49 claim-shaped refs on this tree, 0 unresolved. CHANGELOG and ADOPTION-LOG are exempt: a record *quotes* the wrong version while correcting it. The fix is never to invent a number — write `· unreleased` |
| 35 | the **template's universal-concept list differs from `UNIVERSAL_FLOOR`**. `docs/SKILL-TEMPLATE.md` listed 12 concepts while the floor pinned 25 (found 2026-09-25 by the OWASP gap-check; `docs/INDEX.md` repeated the 12). The floor already fails CI for a *registered* language on every edit, so the drift hurt only the next skill written from the template, which is exactly the reader the template exists for. Set equality, both directions |
| 36 | a **router row reading "Any … code" has no entry in `LANGS`** (`scripts/gen-skill-map.py`), or `LANGS` lists a skill the router no longer routes as a language. The floor check and the skill map see only `LANGS`, so an unregistered tenth language would pass as checked while never being checked. Added 2026-09-25 on operator instruction, before any instance |
| 37 | a **`grep` probe in a skill file combines `--include` with an explicitly named file the glob does not match** — `--include` filters named files too (BSD grep, ugrep and GNU grep, measured 2026-09-25), so the probe exits 1 like a clean codebase. Three shipped probes had it: a Sinatra CSRF check that read HIGH on every app, a Rack session-cookie check that could never fire, a .NET secrets sweep that never opened `appsettings.json`. The sweep that found them first missed the known case because it split on `\|` before reading quotes — a positive control caught it. `# BAD` on the same line exempts a deliberate bad example; probe 37b proves the marker exempts only its own line. **Extended the same day to brace globs** (`--include='*.{py,js}'` matches no file on any grep, since grep never brace-expands; two shipped probes had it, found by the full-library sweep); probe 37c |
| 38 | a **claim about what is current or latest carries a version number** ("the current release is 3.x", "Baseline: Java 25 LTS", "iOS 26 current", "(2026 baseline)"). The pin policy had been prose since the 2026-07-08 sweep and the Go skill's baseline still sat on an out-of-support release until the 2026-09-25 sweep. The detector was rebuilt corpus-first after a regex patched round by round missed bold, wrapped and whitespace-varied shapes; it runs `--self-test` against its labelled corpus before scanning, so a detector regression fails the gate (probe 38b) rather than reading as a clean tree |
| 39 | a **branch edits a rules file an ADOPTION-LOG deferral is waiting on** (its trigger is an edit: "the next rules/03 edit", "the next email-law edit") **and leaves that deferral's row untouched**. Check 27 asserted every deferral *names* a trigger; nothing noticed when one *fired*. #481 fired two and #482 fired four, found only at the next session's close; replayed against both commits, this check flags exactly those rows and passes #487/#488. The detector (`scripts/lib/check-deferral-triggers.py`) resolves each trigger to its file from the row itself — the skill and `rules/NN` in the subject or the trigger — and runs a labelled `--self-test` first. Satisfied by touching the row: flip it to RESOLVED, or annotate *"trigger fired <date>: …, still due"*. An edit trigger that names no file is printed `UNRESOLVED` and not enforced (2 of 20 at introduction, 2026-09-30; **0** once those rows and a relative "the same" trigger were rewritten to name their file the same day). **Drifted back to 5 of 18 by 2026-10-25**, unnoticed because the line prints and never fails: two triggers named their file by path (a script; a rules file written as a full path), which the skill-only resolver could not read, and three named it in words ("the router", "those three files"). The resolver now also guards a backticked tracked path in the trigger clause (probe 39d), the three were rewritten to name their path, and it reads **0 of 18** again |
| 40 | a **command (`commands/*.md`) cites a skill's `rules/NN` but never tells the agent to load that skill**. A citation loads nothing: `/sota-resume` and `/sota-close` cited `sota-shell-scripting` rules/06 six times each, with zero routing instructions, so a resume pass ran ten sweeps without the file and two of its defects were ones rules/06 prevents (field report 2026-10-11; a closure pass repeated it 2026-10-12). Passes on a route-and-walk step (the router's routing table, then each rules file) or an explicit invoke/load/read naming each cited skill; escapes are pinned in the script with a reason, and an unneeded one fails |
| 41 | the router's **§BUILD** changes and `ROUTER_BUILD_SHA` in `evals/run-completeness.py` is not re-read — that pin only fired when the paid eval ran, so under the 2026-10-14 freeze a stale `BUILD_WORKFLOW` could sit indefinitely (PR #119 drifted four days). Same shape as 20; the gate reads the pin and the algorithm from the eval, so they cannot disagree. Bump per `sota/rules/02` §5 |
| 42 | a **rules file reachable only by its own index row**, a **domain AUDIT section that skips rules files**, or a **`rules/NN` / "Load NN" naming a file that does not exist** — the 2026-10-24 library-wide review found nine index-only files, an identity sweep listing "01–06" that never reached the 07 added later, and AUDIT steps loading "the files matching what exists", which skip the file whose probe checks for something absent; every link still resolved, so 8 and 18 stayed green. `scripts/reachability-graph.py` builds the rules-file graph (`--json`, `--explain <file>`) and checks it. Not checkable in general: whether a trigger fires for the right task — **except for a skill that declares its routing** in `scripts/skill-manifests/` (C4, piloted on `sota-rust` and `sota-identity-access`): its tags must appear in each file's routing prose, its `via` hops must be real links, and its labelled cases — the real incidents — must reach their files C4 reads a BUILD list *item* (marker line plus continuations), not a physical line, since 2026-10-26: a wrapped step's routing words above its link were invisible (probe 42g) **C5** (2026-10-26, stage 3's generated half): a rules-index row is written in its manifest's `index_row` and rendered into SKILL.md by `--write-index`; a row edited in SKILL.md alone fails (probe 42h) |
| 43 | a **numbered section no checklist item cites**, a **checklist item citing no section**, or a **new rules file without numbered sections** — the BUILD-rule-without-probe gap is the library's most rediscovered (54 S1 candidates in the 2026-10-24 review), and at section granularity the correspondence is mechanical: `(§N)`. A ratchet over `scripts/section-sync-baseline.json` (1,246 uncited sections, 3,124 uncited items at introduction): new work complies or is marked `*(advisory)*` / `*(audited in …)*`, a fixed entry must leave (`--sync-tighten`), and the baseline may not grow against the merge base. Whether the citing item really detects the violation stays semantic. **Blind until 2026-10-25 to dotted headings** (`## 6.1`): all 20 rules files of `sota-devsecops` and `sota-testing` read as unnumbered, so two of the most security-relevant skills sat outside the ratchet. The parser now reads dotted ids, a cite of `§6.3.2` counts for 6, 6.3 and 6.3.2, and `--sync-convert` moves a file that was unnumbered **at the merge base** from file-level to section-level debt without tripping the growth rule (probes 43e, green, and 43f, a bogus entry riding the exemption, caught by S4). Converting the 20 surfaced 88 uncited sections: **1,305** after, against 1,217 before. The other 38 files were then numbered and converted the same day (260 headings; uncited items of a converted file are converted debt too, since S2 had skipped them), leaving **0 unnumbered** and **1,565** uncited sections. From then on no file can be unnumbered at a merge base (S3 forbids new ones), so the conversion exemption is dormant and probes 43e/43f skip with that reason. **Three more false readings, fixed 2026-10-26:** a `## N.` inside a fenced code block counted as a section (7 phantoms, one template; probe 43g, green); another file's shorthand cite (`` `04` §8 ``) or an RFC's (`RFC 9110 §15.6.4`) credited the local section (probes 43h, 43i). Sections and items reached **0** and **925** uncited, and the item paydown the same day **84**, then **0** once those (each auditing another file's rule or an unnumbered preamble) were re-homed |
| 44 | a **checklist probe nobody proved detects anything** — invariant 43 proves an item cites its section and `check-checklist-probes.py` that its grep runs, but neither shows the probe catches the defect: that script's own docstring said "only a known-bad fixture per probe catches those".
